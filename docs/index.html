QA Cortex Repository Guide

Every folder and file in the repository, what it does, and how the pieces work together. Last updated 26 November 2026.

Framework (library) Starter project CI / GitHub Generated, not in Git

0The big picture

The repository holds two independent npm projects, each with its own package.json and lockfile. They are connected only through a packed tarball: the starter project never imports framework source files directly.

framework/
@qa-cortex/core

The library: configuration, logging, secrets, production guard, reporting presets. Tested in CI on Linux and Windows.

→packed into
vendor/qa-cortex-core.tgz
automation/
starter project

A ready-to-use Playwright project: page objects, test data, fixtures, sample tests, reports.

.github/workflows/ checks the framework on every pull request, and runs the starter project's tests on demand.
One rule shapes everythingQA Cortex extends Playwright and never replaces it: no wrapped actions, no base page class, no custom runner. Raw Playwright always stays usable, and every core module works on its own.

3.3 The five modules in src/

Each folder is a separate module with its own index.ts, the public entry that decides what users can import. Modules never import each other. Their fixtures cooperate only through fixture names: for example, the secrets module reads a fixture called qaConfig without importing the config module.

src/config/ Typed, layered configuration

Environment profiles validated before any browser starts. ADR 0002.
index.tsPublic entry.
schema.tscoreSchema: the built-in fields baseURL, production, api, ai. Projects add fields with coreSchema.extend().
load.tsdefineQaConfig() declares base and profiles; loadConfig() picks the profile (from QA_CORTEX_PROFILE), merges, validates and freezes.
merge.tsLayered deep merge: defaults → base → profile → overrides. Remembers which layer set each value, so errors say "set in profile staging". Internal.
freeze.tsDeep-freezes the result so tests can't change config by accident. Internal.
errors.tsConfigError: every problem at once, with its layer, never the values.
fixtures.tsconfigFixtures(): the qaConfig and qaProfile fixtures.
reserved.tsReserves the api and ai sections for future packages.
types.tsType helpers (DeepPartial, DeepReadonly) mirroring the merge and freeze rules.

src/logger/ Structured, redacting logging

A per-test logger whose output hides secrets. ADR 0007.
index.tsPublic entry.
logger.tscreateLogger(): levels, child() context, writing to a sink.
redact.tsReplaces known secret values (plain or URL-encoded), and values under sensitive keys such as password or token, with [REDACTED]. Internal.
format.tsOutput formats: the terminal line ([info] msg {"data":1}) and the JSON line used in the attachment.
fixtures.tsloggerFixtures(): the per-test qaLog, the options qaLogLevel and qaLogAttach, and the qaSecrets slot. Attaches qa-cortex-log.jsonl to the report.
types.tsLogLevel, LogRecord, Logger.

src/secrets/ Typed secrets per profile

Secrets from the environment or .env, never printed. ADR 0008.
index.tsPublic entry.
load.tsdefineSecrets() says which environment variable holds each secret, per profile; loadSecrets() reads and validates them (rejects missing, empty or very short values).
secret.tsThe Secret class: prints as [REDACTED] everywhere; only reveal() returns the value.
fixtures.tssecretsFixtures(): the qaSecretStore fixture. Feeds every secret to the logger for redaction; its qaSecretsCheck fails the run if fixtures are composed in an order that would switch redaction off.
errors.tsSecretsError: names the secret and variable, never the value.
types.tsTyping for secret definitions and the store.

src/guard/ Production guard

Refuses to record traces, videos or screenshots in a production profile. ADR 0003 and 0008.
index.tsPublic entry.
check.tsThe rules: in production, trace, video and screenshot must be off; HTML and blob reporters are flagged.
assert.tsassertProductionSafe(): the static check, called at the end of playwright.config.ts.
fixtures.tsproductionGuardFixtures(): the runtime check, an automatic worker fixture. Also catches --trace on from the command line, before any browser opens.
errors.tsProductionGuardError.
types.tsTypes for the settings the guard reads.

src/presets/ Reporter and artifact presets

Ready-made reporters and artifact settings for local, CI and production runs. ADR 0009.
index.tsPublic entry.
select.tsselectPreset(): production for a production profile, otherwise QA_CORTEX_PRESET, then ci when CI is set, then local.
preset.tsqaPreset(): returns a ready reporter list and use settings for playwright.config.ts.
artifacts.tsTrace, video and screenshot settings per preset.
reporters.tsThe reporter list per preset and the override rules (html, junit, json, extra such as Allure, or replace). Checks that report paths don't collide.
errors.tsPresetError.
types.tsPreset types.

6How one test run flows through the files

  1. npm test → Playwright loads automation/playwright.config.ts.
  2. The config loads .env, then calls loadConfig(qaConfig) (qa.config.ts → src/config/load.ts) and loadSecrets(…) (qa.secrets.ts → src/secrets/load.ts). Bad input stops the run here, before any browser starts.
  3. qaPreset(selectPreset(…)) from src/presets/ supplies the reporters and trace, video and screenshot settings, and Allure is added. assertProductionSafe() from src/guard/assert.ts checks the result.
  4. Each worker sets up the fixtures from tests/fixtures.ts: qaConfig, the runtime guard, qaLog, qaSecretStore, then page objects such as textBoxPage.
  5. A spec such as tests/ui/dropdown.spec.ts reads data/dropdown.json, calls the page object pages/dropdown.page.ts, and asserts with plain Playwright expect.
  6. Playwright writes the reports; the logger attaches qa-cortex-log.jsonl with secrets redacted.

7Where new framework features would go

A new core module follows the same pattern as the existing five:

  • Code: a folder framework/packages/core/src/<module>/ with index.ts, the implementation, fixtures.ts, errors.ts and types.ts.
  • Public subpath: an entry in packages/core/package.json exports.
  • Tests: test/<module>/, a nested test/fixtures/pw-<module>/ project, and test/types/<module>.types.ts.
  • Decision record: a new ADR in framework/docs/adr/.
  • Starter project: a fixture in automation/tests/fixtures.ts, an example spec and a README section.

A larger area, such as API automation or AI agents, would become a new package in framework/packages/ instead, as CLAUDE.md plans.

Candidates for the next framework featureAuthentication (roles and reusable sessions: in development, paused), the cleanup registry (pending), shared ESLint and TypeScript configuration packages (pending, waiting on the ESLint 9 → 10 decision), npm publishing (pending), and later the API and AI packages.
